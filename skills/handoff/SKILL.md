# 작업 인계

다음 작업자가 대화 기록 없이도 이어서 작업할 수 있는 `HANDOFF.md`를 작성한다.
성공한 결과만 요약하지 말고, 결정의 이유와 실패한 접근을 남기는 것이 핵심이다.

## 작성 위치

기본 위치는 저장소 루트다. 특정 모듈 안에서만 의미가 있는 작업이면 해당 모듈에
둔다. 기존 `HANDOFF.md`가 있으면 현재 git 상태와 대조한 뒤 갱신한다.

## 먼저 확인할 것

문서를 쓰기 전에 다음을 직접 확인한다.

- `git status --short`
- 현재 branch와 최근 commit
- 변경된 파일과 실제 diff
- 마지막으로 실행한 테스트 결과
- 진행 중인 plan이나 issue가 있다면 그 원문

기억에 의존해 완료 상태를 쓰지 않는다. 확인하지 못한 항목은 `미확인`이라고 표시한다.

## 문서 구조

```markdown
# Handoff: <작업 이름>

## 목표와 현재 상태
- 목표:
- 현재 상태: 완료 | 진행 중 | 막힘
- 다음 작업자가 먼저 할 일:

## 결정과 이유
- <결정>: <선택한 이유와 버린 대안>

## 변경 사항
- `path/to/file`: <무엇을 왜 바꿨는지>

## 검증
- `<실행한 명령>`: PASS | FAIL
- 실행하지 못한 검증과 이유:

## 실패한 접근
- <시도>: <실패 원인과 다시 시도하지 않기 위한 조건>

## 남은 작업
1. <파일과 완료 조건이 포함된 다음 행동>

## 주의할 점
- <환경, 의존성, 보안, 데이터 관련 제약>
```

## 작성 기준

- 파일 경로, 함수 이름, 명령어를 정확히 쓴다.
- `잘 안 됨`, `나중에 확인`처럼 다음 행동을 만들 수 없는 표현은 쓰지 않는다.
- 테스트는 실행한 명령과 결과를 함께 적는다. 통과했다고 추정하지 않는다.
- 실패 원인은 관찰된 사실과 추측을 구분한다.
- 다음 단계에는 완료 조건을 넣는다.
- diff에서 확인할 수 있는 내용을 장황하게 복사하지 말고 판단과 맥락에 집중한다.

문서를 작성한 뒤, 새 세션이 이 파일 하나만 읽어도 첫 행동을 결정할 수 있는지 한 번
점검한다.
