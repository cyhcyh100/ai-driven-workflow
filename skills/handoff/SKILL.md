# 작업 인계 지침

다음 에이전트가 새로운 컨텍스트로 작업을 이어받을 수 있도록 `HANDOFF.md` 파일을 작성합니다.

## 작성 위치

현재 작업 디렉토리의 적절한 위치에 `HANDOFF.md` 파일을 생성하세요. 작업 맥락에 따라 다음 중 하나를 선택:
- 프로젝트 루트 디렉토리
- 작업 중인 기능/모듈 디렉토리
- 특정 하위 디렉토리 (예: `system-prompt-extraction/`)

## 파일 구조

다음 섹션을 포함하여 체계적으로 작성하세요:

### 1. 작업 개요
```markdown
## 작업 개요

**목표**: [무엇을 달성하려고 했는지]
**현재 상태**: [어디까지 진행되었는지]
**남은 작업**: [무엇이 남았는지]
```

### 2. 시도한 접근 방법
```markdown
## 시도한 접근 방법

### 접근 방법 1: [방법 이름]
- **시도 내용**: [무엇을 했는지]
- **결과**: [성공/실패]
- **이유**: [왜 그런 결과가 나왔는지]

### 접근 방법 2: [방법 이름]
- **시도 내용**: [무엇을 했는지]
- **결과**: [성공/실패]
- **이유**: [왜 그런 결과가 나왔는지]
```

### 3. 작동한 것
```markdown
## 작동한 것 ✓

1. **[성공한 작업 1]**
   - 파일: `path/to/file.ts`
   - 방법: [어떻게 했는지]
   - 결과: [어떤 결과를 얻었는지]

2. **[성공한 작업 2]**
   - 파일: `path/to/file.ts`
   - 방법: [어떻게 했는지]
   - 결과: [어떤 결과를 얻었는지]
```

### 4. 작동하지 않은 것
```markdown
## 작동하지 않은 것 ✗

1. **[실패한 작업 1]**
   - 시도: [무엇을 시도했는지]
   - 문제: [왜 작동하지 않았는지]
   - 교훈: [무엇을 배웠는지]

2. **[실패한 작업 2]**
   - 시도: [무엇을 시도했는지]
   - 문제: [왜 작동하지 않았는지]
   - 교훈: [무엇을 배웠는지]
```

### 5. 중요한 발견사항
```markdown
## 중요한 발견사항

- **코드베이스 구조**: [코드베이스에 대해 알게 된 중요한 정보]
- **의존성**: [관련된 파일이나 모듈]
- **제약사항**: [작업 중 발견한 제한사항]
- **주의사항**: [다음 작업자가 알아야 할 주의사항]
```

### 6. 다음 단계
```markdown
## 다음 단계

### 즉시 시도할 것 (우선순위 높음)
1. [구체적인 다음 액션 1]
   - 이유: [왜 이것을 시도해야 하는지]
   - 파일: [수정할 파일들]

2. [구체적인 다음 액션 2]
   - 이유: [왜 이것을 시도해야 하는지]
   - 파일: [수정할 파일들]

### 고려할 대안
- [대안 1]: [설명]
- [대안 2]: [설명]
```

### 7. 참고 자료
```markdown
## 참고 자료

- 관련 파일:
  - `path/to/important-file.ts`: [이 파일의 역할]
  - `path/to/another-file.ts`: [이 파일의 역할]

- 관련 문서:
  - [문서 링크 또는 위치]

- 테스트 명령어:
  ```bash
  pnpm test path/to/test
  ```
```

## 작성 원칙

1. **구체적으로**: 추상적인 설명보다 구체적인 파일 경로, 함수 이름, 코드 스니펫을 포함
2. **맥락 제공**: 왜 특정 접근을 시도했는지 배경 설명
3. **실패 공유**: 실패한 시도도 중요한 정보 - 다음 작업자가 같은 실수를 반복하지 않도록
4. **실행 가능하게**: 다음 작업자가 파일만 읽고 바로 시작할 수 있도록 명확한 다음 단계 제시
5. **핵심만**: 중요한 정보에 집중, 불필요한 세부사항은 생략

---

이 스킬을 사용하면 컨텍스트 제한에 도달했을 때나 작업을 다른 세션으로 넘길 때 효과적으로 지식을 전달할 수 있습니다.
